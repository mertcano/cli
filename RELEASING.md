# Releasing

Releases are automated via GoReleaser and GitHub Actions. Pushing a tag triggers the release pipeline.

## Steps

1. Make sure all changes are merged to `main`.

2. Choose a version following [semver](https://semver.org/) (e.g. `v1.2.3`).

3. Tag and push:

   ```bash
   git tag v1.2.3
   git push origin v1.2.3
   ```

4. GitHub Actions runs the `CLI Release` workflow, which:
   - Builds binaries for `darwin/amd64`, `darwin/arm64`, `linux/amd64`, `linux/arm64`
   - Creates archives: `qfex_1.2.3_darwin_arm64.tar.gz`, etc.
   - Builds Debian packages for `linux/amd64` and `linux/arm64`
   - Generates `checksums.txt`
   - Publishes a GitHub Release with all assets attached
   - Updates the Homebrew tap

5. Monitor the run at `https://github.com/QFEX-org/cli/actions`.

## Artifacts

Each release produces:

| File | Description |
|------|-------------|
| `qfex_1.2.3_darwin_amd64.tar.gz` | macOS Intel |
| `qfex_1.2.3_darwin_arm64.tar.gz` | macOS Apple Silicon |
| `qfex_1.2.3_linux_amd64.tar.gz` | Linux x86-64 |
| `qfex_1.2.3_linux_arm64.tar.gz` | Linux ARM64 |
| `qfex_1.2.3_linux_amd64.deb` | Debian/Ubuntu x86-64 |
| `qfex_1.2.3_linux_arm64.deb` | Debian/Ubuntu ARM64 |
| `checksums.txt` | SHA256 checksums for all artifacts |

Asset names drop the leading `v` from the tag: tag `v1.2.3` produces `qfex_1.2.3_*`.

The `.deb` packages install `/usr/bin/qfex` plus bash, zsh, and fish completions under
`/usr/share`. They are built by the `nfpms` section of `.goreleaser.yaml`, which reads the
completion scripts generated by the `before` hooks into `completions/` (git-ignored).

`install.sh` (served from `main` via raw.githubusercontent.com, and the install path the README
advertises) resolves the newest tag from the GitHub releases redirect and then constructs asset
names as `qfex_<version>_<os>_<arch>.{deb,tar.gz}`, checking them against `checksums.txt`. Changing
`project_name`, the archive `name_template`, or the nfpm file naming will break it — update
`install.sh` in the same change.

## Fixing a bad release

Tags cannot be re-used. To re-release the same logical version:

1. Delete the tag locally and remotely:
   ```bash
   git tag -d v1.2.3
   git push origin :refs/tags/v1.2.3
   ```
2. Delete the draft/published GitHub Release if one was created.
3. Re-tag with a patch bump (e.g. `v1.2.4`) instead.

## Local dry run

To test the GoReleaser config without publishing:

```bash
goreleaser release --snapshot --clean
```

Artifacts are written to `dist/`. Requires [GoReleaser](https://goreleaser.com/install/) installed locally.

Inspect a built package with:

```bash
dpkg-deb -I dist/qfex_*_linux_amd64.deb   # control metadata
dpkg-deb -c dist/qfex_*_linux_amd64.deb   # file list
```
